## 1. 왜 이 단계가 필요한가

Phase 0~5에서 기능은 모두 들어갔고 자동 검사는 통과했다. 그러나 PRD 기준으로 보면 아래가 남아 있다.
"UI가 있다는 이유만으로 완료로 표시하지 않는다"(PRD §7)는 규칙 때문에, 이 항목들이 닫혀야 MVP 완료라고 말할 수 있다.

## 2. 범위

- 포함: 위 표의 빠진 항목, 모바일·접근성 다듬기, 오류·복구, 개인정보·약관·라이선스 화면, 보안 헤더, 실제 허밍 품질 측정,
  베타 후보 배포, 전체 수동 회귀(UAT), 결함 수정, MVP 인수 보고서.
- 제외(PRD §6 그대로): 로그인·클라우드 동기화, 결제, 분석 도구 도입, 다성 채보, 음원 파일 가져오기, MIDI 장치 입력, 정간보.
- 새 기능을 더 넣는 단계가 아니다. PRD에 있는데 빠진 것을 채우고, 있는 것을 실제 기기에서 확인하는 단계다.

## 3. 유지하는 계약

- Score schemaVersion 2, `Part.ties`, IndexedDB DB2, ADR-010 revision/CAS/Tombstone, Command/Undo 흐름, Domain 독립성은 그대로.
- 연습 속도·A–B 반복·선택·라벨·녹음은 Score·JSON·저장 이력에 넣지 않는다.
- 녹음은 메모리에만 두고 업로드하지 않는다. 서버에 사용자 데이터를 보내는 기능을 만들지 않는다.
- 테스트 삭제·skip·기대값 약화 금지. 실제 청취·Safari·실기기 결과는 따로 기록하고, 하지 않은 것은 NOT RUN으로 적는다.
- push·배포·도메인·외부 서비스 연결은 각각 사용자 승인 후에만 한다.

## 6. 검증

- 작업마다 `npm run typecheck`, `npm run lint`, `npm run test`, `npm run check:architecture`, `npm run build`, UI 변경 시 전체 `npm run test:e2e`.
- 새 자동 검사: axe 접근성(주요 화면), 키보드만으로 하는 최종 인수 시나리오, 모바일 크기(Playwright 기기 에뮬레이션) 여정, CSP 위반 0건.
- 수동: 전체 UAT(결정 11), VoiceOver 점검, 실제 허밍 평가(결정 9).
- 마지막에 **MVP 인수 보고서**(14개 그룹별 기준·증거·미확인 항목)를 만든다.

## 7. 범위 밖

로그인·동기화·결제·분석 도구, 도메인 구입, 마케팅 페이지, 가격 정책, 다국어(영어) UI는 이 계획에 포함하지 않는다.
베타 사용 결과를 본 뒤 별도로 결정한다(PRD §9: 지표·가격은 실제 사용 증거 이후).
