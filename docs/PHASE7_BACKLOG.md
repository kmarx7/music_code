### 트랙 A — 화면 흐름

#### A-1 — 화면 설계 — Done (2026-11-14, 시안 권장안대로 승인)
- ui-craft 절차: 현재 화면 점검 → `/record` 4단계·`/new`·편집기 4모드의 시안(데스크톱·휴대폰) → 사용자 확인.
- 정할 것: 단계 표시 방식, "뒤로·취소" 위치, 모드 전환 막대 위치(데스크톱), 각 모드의 도구 배치.
- 수용: 사용자가 시안을 승인. 코드 변경 없음.
- 확정(권장안): ① 데스크톱도 "악보 위 + 모드 막대 + 도구 아래"(악보 높이 제한·내부 스크롤) ② 제목은 상단 "이름 바꾸기" ③ 휴대폰 모드 막대는 화면 아래 고정 ④ 허밍 ①에서 조성은 묻지 않음(C장조, 다듬기에서 변경) ⑤ 남색 #1b2a4a·시스템 글꼴 유지, 최소 색·모서리 변수(`--hb-*`)만 추가.

#### A-2 — `/new` 피아노 시작 (결정 3) — Done (2026-11-14, 커밋 전)
- 제목·박자·템포·조성·목표 악기(B 전까지는 피아노만 선택 가능) → "만들기"에서 저장, 편집기 입력 모드로.
- 홈 "피아노로 시작"이 여기로. `/editor/<id>?start=piano`는 편집기 입력 모드로 열리도록 유지.
- 수용: 취소 시 악보 미생성, 만들기 1회 = 악보 1개(더블클릭 포함), 설정값이 악보에 들어감.

#### A-3 — 편집기 작업 모드 (결정 4) — Done (2026-11-14, 커밋 전)
- 기존 휴대폰 탭(P6-03)을 데스크톱까지 확장: 입력 / 다듬기 / 연습 / 내보내기. 악보는 항상 위.
- 도구 이동만 하고 기능 계약(Command·저장·출력)은 바꾸지 않는다.
- 수용: 모든 기존 기능에 모드 전환으로 도달, 모드 전환이 편집·Undo·재생 상태를 잃지 않음, axe 0건, 키보드 이동.

#### A-4 — `/record` 허밍 단계 흐름 (결정 2) — Done (2026-11-14, 커밋 전)
- ① 기본 설정 ② 마이크 준비 ③ 녹음 ④ 확인. 기존 녹음 모듈(캡처·카운트인·분석·후보)을 재사용하고, 악보는 ④ 확정 때 저장.
- 수용: 어느 단계에서 나가도 악보·녹음 미저장, 다시 녹음, 확정 1회 = 악보 1개 + 채보 음, 녹음 데이터 비저장, 권한 거부 안내.
- 구현 기본값: 입력 레벨은 ② 대신 ③(카운트인부터)에서 보인다. 마이크를 ②에서 미리 열면 권한 요청·캡처 경로가 두 벌이 되기 때문이다. ②에는 동의·메트로놈·이어폰 안내만 둔다.

#### A-5 — "허밍 추가" — Done (2026-11-14, 커밋 전)
- 편집기 입력 모드에서 같은 흐름을 기존 악보 대상으로(① 설정은 악보 값 고정, ④에서 끝/커서 위치 선택). 기존 PasteEvents 1회 Undo 유지.
- 구현: 입력 모드 패널은 접힌 상태(설명 + "허밍 추가")로 시작한다. 열면 단계 목록 "1 설정 ✓ · 2 마이크 · 3 녹음 · 4 확인"으로 ②부터 보인다(① = 악보의 템포·박자·조성, 여기서 바꾸지 않음). ② 동의·메트로놈·"닫기"/"녹음 시작", ③ "취소"(②로)/"녹음 정지", ④ 후보·넣을 위치·미리보기·"후보 버리기"/"다시 녹음"/"악보에 넣기". 넣으면 접히고 안내를 보인다.
- 구현 기본값: ① 화면을 따로 두지 않았다(바꿀 값이 없으므로 클릭만 늘어난다). ④에는 `/record`와 달리 미리듣기 재생을 두지 않았다(편집기 연습 모드의 재생 버튼과 이름이 겹치고, 미리보기 악보는 위치 확인용).
- 공통 모듈: 녹음 한 번의 상태·캡처·분석을 `useHummingTake`로, 단계 목록·마이크 준비·녹음 표시·후보 칩을 `take.tsx`로 분리해 `/record`와 같이 쓴다.

#### A-6 — E2E 이전·회귀 (결정 10) — Done (2026-11-14, A-5 포함)
