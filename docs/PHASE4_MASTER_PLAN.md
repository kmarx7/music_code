- 작성: 2026-11-13, Claude Code. 기준 코드: main `c89719e`.
- 대상 요구사항: PRD MVP-002(마이크 캡처), MVP-003(단선율 채보). 실행 단위는 [PHASE4_BACKLOG](PHASE4_BACKLOG.md).
- 상태: **계획 승인, P4-01부터 순차 진행.** 2026-11-13 사용자가 이 계획의 문서화와 결정 1~8의 권고안 채택을 지시했다(§4).
  각 작업의 구현·검증 상태는 백로그와 [TASKS](TASKS.md)에 기록한다. 이 문서의 수치 목표는 달성 실적이 아니다.

## 1. 목표와 범위

미리 정한 빠르기·박자로 짧은 단선율 허밍(4–8마디)을 녹음하면, 편집·저장 가능한 음표 후보가 만들어지고
사용자가 검토한 뒤 확정한다.

| 구분 | 내용 |
|---|---|
| 포함 | 마이크 동의·권한, 녹음 시작/정지, 경과 시간·입력 레벨, 음높이 추정, 무음/신뢰도 판별, 음 경계·같은 음 반복 분리, 박자 격자 맞춤, 후보 검토, 원자 확정 |
| 제외(PRD 그대로) | 다성음, 상용곡 분리, MP3/WAV 가져오기, 녹음 업로드·서버 전송, 녹음의 영구 저장, 전곡 채보 |
| 뒤로 미룸 | 실시간 음높이 표시(결정 3), Worker 분석(결정 2에서 필요해질 때만) |

## 2. 유지하는 계약

- 단일 canonical Score(schemaVersion 2, `Part.ties`), IndexedDB DB2, ADR-010 revision/CAS/Tombstone은 바꾸지 않는다.
- 녹음 원본(PCM)과 프레임별 분석값은 **메모리에만** 둔다. Score·JSON·저장 이력·IndexedDB에 넣지 않고 업로드하지 않는다.
- 채보 결과는 두 번째 편집 Score가 아니라 **후보**다. 확정은 기존 Command/Undo/Redo 흐름의 Command 하나로 하고
  Undo 한 번으로 전부 되돌린다. 분석 실패·취소·권한 거부는 기존 Score와 이력을 바꾸지 않는다.
- 음높이·분할·격자 계산은 Domain의 순수 함수다(브라우저·React·Tone·VexFlow·IndexedDB 비의존).
  마이크·오디오 그래프는 adapter에만 둔다. Application은 포트만 참조한다.
- 표기할 수 없는 길이는 조용히 근사하지 않는다(H-02). 마디를 넘는 음은 기존 타이 분할을 재사용한다.
- `provenance.source`/`confidence`는 기존 타입 범위에서만 쓴다. 새 음악 필드는 별도 승인 대상이다.

## 3. 처리 흐름

```text
사용자 동작 → 마이크 권한 → PCM 캡처(메모리) → [정지]
  → 프레임별 음높이·신뢰도 → 무음 판별·평활화·옥타브 보정
  → 음 경계·같은 음 반복 분리 → 빠르기/박자 격자 맞춤
  → 후보 음표/쉼표 → 사용자 검토(낮은 신뢰도 표시) → 확정 Command 1개 → 기존 자동 저장
```

## 5. 품질 측정 정의 (C-09)

- 단위: 음표. 기준 선율과 채보 결과를 `{ midi, startTick, durationTicks }` 목록으로 비교한다.
- 일치(TP): 같은 MIDI 번호이고 시작 위치가 같은 격자(기본 허용 오차 0 tick)인 음표의 일대일 대응.
- precision = TP / 결과 음표 수, recall = TP / 기준 음표 수, F1 = 2·TP / (2·TP + FP + FN). 분모가 0이면 1로 둔다.
- 함께 기록: 옥타브 오류 수(시작 위치는 맞고 12의 배수만큼 다른 음), 그 밖의 음높이 오류 수, 길이까지 일치한 비율.
- 데이터: (a) 코드로 만든 합성음 — 깨끗한 음, 비브라토, 음 시작의 끌어올림, 잡음, 전체 음정 어긋남, 같은 음 반복, 쉼표, 도약.
  (b) 사용자가 동의한 실제 허밍(결정 7). **합성음 수치는 실제 허밍 품질을 보증하지 않는다.**

## 7. 검증

- 작업마다 `npm run typecheck`, `npm run lint`, `npm run test`, `npm run check:architecture`, `npm run build`,
  UI 변경 시 전체 `npm run test:e2e`.
- 마이크가 필요한 흐름의 자동 테스트는 가짜 입력(합성 PCM)으로 한다. 이는 실제 마이크·실제 허밍의 대체가 아니다.
- 실제 허밍·Safari·실기기는 수동 UAT로 따로 기록하고, 미실행은 NOT RUN으로 명시한다.
- Phase 5(PDF/MIDI/MusicXML)와 Phase 6(인수·배포 준비)은 이 계획의 범위가 아니며 별도 승인 대상이다.
