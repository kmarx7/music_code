## 1. 왜 이 단계가 필요한가

### 1.1 화면 흐름 (트랙 A)

| 지금 (2026-11-14 코드) | 문제 |
|---|---|
| 홈의 "허밍으로 시작"·"피아노로 시작"이 둘 다 새 악보를 즉시 만들고 같은 편집기로 간다. 차이는 스크롤 위치와 동의 체크 포커스뿐(`src/app/editor/[scoreId]/page.tsx:177-188`) | 사용자는 두 버튼의 차이를 느끼지 못한다. 중간에 그만두면 빈 악보가 악보함에 남는다 |
| 데스크톱 편집기는 입력·녹음·재생·연습·조옮김·구간 편집·출력 패널이 한 페이지에 세로로 나열된다. 휴대폰만 탭 4개(P6-03) | "쭉 늘어놓은" 느낌. 처음 온 사람이 무엇부터 할지 알 수 없다 |
| 녹음 전 설정(템포·박자)이 녹음 패널 안에 섞여 있다 | 녹음 품질에 직접 영향을 주는 설정인데 눈에 띄지 않는다 |

조사 결론(대화 기록, 출처 포함): 녹음 우선 앱(ScoreCloud, Music Memos, Hum On!, Humming Score)은 **녹음 → 분석 → 확인·수정 → 조옮김·출력**이 일렬이고,
기보 앱(MuseScore, Finale, Flat)은 **새 악보 설정 → 편집 작업 공간**이다. 단계형(마법사)은 뒤 단계가 앞 선택에 의존하고 처음 하는 일일 때 맞고,
반복해 고치는 편집에는 맞지 않는다(NN/g). 따라서 **시작(설정 → 마이크 → 녹음 → 확인)만 단계형, 이후는 작업 모드로 나눈 편집기**로 바꾼다.

### 1.2 국악기 악보 (트랙 B)

- 목표: 지금의 악보(단선율)를 **향피리 또는 25현 가야금이 실제로 연주할 수 있는 오선보**로 맞춰 준다. 정간보·시김새 자동 생성은 하지 않는다.
- 기존 자산: 음역 분석과 조옮김 추천(MVP-011, `analyzeScoreRange`, `recommendTranspositions(score, target)`), 조옮김 확정(MVP-007), 낮은음자리표, 라벨 오버레이(MVP-010).
  → 국악기 기능의 핵심은 **악기별 목표 음역·조율을 이 기능들에 넣어 주는 것**이며, 새 엔진이 거의 필요 없다.
- 조사로 확인한 값(2026-11-14, 확정 전 임시):

| 악기 | 확인한 값 | 출처 | 확정 필요 |
|---|---|---|---|
| 향피리 | 기본 음역 탁중려(A♭3) ~ 청태주(F5), 약 1옥타브 반. 세피리도 같음 | 국립국악원 국악사전 | 오선보를 **실음**으로 적는지 이조하는지, 평취·역취 등 실용 상한 |
| 25현 가야금 | 7음계 조율, 곡에 따라 조율을 바꾼다. 다장조 조율 예: E부터 A까지 25줄 | 국립국악관현악단 악기소개, 나무위키 | **줄별 실제 음높이(옥타브)**, 큰보표 사용 여부, 조율 밖 음(누름)의 실용 범위, 표준 조율 목록 |

이 값들은 출처가 엇갈리거나 확인되지 않았다. **B-1(기준값 확정)이 끝나기 전에는 트랙 B 화면을 공개하지 않는다.**

## 2. 범위

- 포함
  - 트랙 A: 단계형 허밍 시작(설정 → 마이크 → 녹음 → 확인), 피아노 시작(설정 1단계), 편집기 작업 모드 4개(데스크톱·휴대폰 공통), "허밍 추가"로 같은 단계 흐름 재사용.
  - 트랙 B: 향피리·25현 가야금 악기 정보, 악기 음역 검사·조옮김 추천, 25현 조율 추천과 "누름 필요" 표시, 음자리표 선택, 출력에 악기 이름.
- 제외: 정간보, 시김새(농현·퇴성·추성·전성) 자동 생성, 해금·12현(정악·산조) 가야금·당피리(다음 단계 후보), 큰보표(두 줄 보표), 국악기 음색 재생(샘플 라이선스 필요), 로그인·결제·서버 저장.

## 3. 유지하는 계약

- Command/Undo 흐름, IndexedDB DB2, ADR-010 revision/CAS/Tombstone, Domain 독립성(브라우저·React·Tone·VexFlow·IndexedDB 의존 금지).
- 연습 속도·A–B 반복·선택·라벨·녹음 데이터·"누름 필요" 표시는 Score·JSON·저장 이력에 넣지 않는다.
- 녹음은 메모리에만 둔다. 서버로 사용자 데이터를 보내지 않는다.
- 테스트 삭제·skip·기대값 약화 금지. 화면 구조가 바뀌어 기존 E2E의 조작 순서가 바뀌는 것은 허용하되, **확인하는 결과(저장·Undo·출력 내용)는 그대로** 둔다.
- Score 형식 변경은 결정 6에서 승인될 때만 한다.

## 4. 결정 (D-05, 2026-11-14 사용자 승인 — 권고안 그대로)

| # | 결정 | 권고안 | 대안과 비용 |
|---|---|---|---|
| 1 | Phase 6 남은 일과의 순서 | **트랙 A를 먼저** 하고, 그 화면으로 Phase 6 전체 UAT(P6-10)를 한 번에 한다. 트랙 B는 A-3(편집기 모드) 뒤. 개인정보·약관(P6-06)과 실제 허밍 녹음(P6-08)은 병행 | UAT를 지금 먼저: 화면이 바뀌면 같은 점검을 다시 해야 한다 |
| 2 | 허밍 시작 흐름 | `/record`(PRD §4의 원래 주소)에 **4단계**: ① 기본 설정(제목, 박자, 템포, 목표 악기. 기본값 4/4·90·피아노, "기본값으로 시작") ② 마이크 준비(동의, 입력 레벨, 이어폰 권장) ③ 녹음(카운트인, 진행, 실시간 음이름) ④ 확인(후보 악보 보기·듣기, 다시 녹음, "악보 만들기"). **악보는 ④에서 확정할 때 처음 저장**. | 3 | 피아노 시작 흐름 | `/new` 한 단계(제목, 박자, 템포, 조성, 목표 악기) → "만들기"에서 저장하고 편집기의 입력 모드로 | 설정 없이 바로 편집기: 지금과 같음 |
| 4 | 편집기 작업 모드 | 악보는 항상 위. 아래 도구를 **입력 / 다듬기 / 연습 / 내보내기** 4개 모드로, 데스크톱도 휴대폰과 같은 모드 전환을 쓴다. 입력 = 건반·길이·커서·"허밍 추가"(결정 2 흐름을 기존 악보에 넣기 모드로), 다듬기 = 음 편집·구간 편집·조옮김·음역 추천·**악기에 맞추기**, 연습 = 재생·속도·A–B·메트로놈, 내보내기 = 저장·JSON·PDF·MIDI·MusicXML. 모드 선택은 저장하지 않는다 | 데스크톱은 지금처럼 나열: 화면 넓이를 쓰지만 구조 문제는 남는다 |
| 5 | 국악기 기준값 확정 | B-1에서 **교본 또는 국악 전공자 확인**으로 표 1.2의 "확정 필요" 값을 정하고 `docs/INSTRUMENTS.md`에 출처와 함께 적는다. 확인자 확보는 사용자 몫 | 조사값 그대로 구현: 틀리면 신뢰를 잃는다 |
| 6 | 악기 정보 저장 | Part에 선택 필드 `instrument`(`"piano" \| "hyang-piri" \| "gayageum-25"`)를 넣고 **schemaVersion 3**으로 올린다. v2 악보·JSON은 읽을 때 `"piano"`로 채운다(이동 코드·테스트 포함). 악기 변경과 음자리표 변경은 각각 **한 Command, 1회 Undo** | 저장하지 않는 보기 설정: 다시 열면 악기가 사라지고 출력에 악기 이름을 못 넣는다 |
| 7 | 악기에 맞추기 동작 | 악기를 고르면 ① 악기 음역 밖 음 개수 표시 ② 기존 조옮김 추천에 악기 음역을 목표로 넣어 후보 제시(확정은 기존 조옮김 Command) ③ 음자리표 제안(25현은 음역에 따라 낮은음/높은음). **음을 자동으로 바꾸지 않고 항상 사용자가 확정** | 자동 변환: 사용자가 모르게 음이 바뀐다 |
| 8 | 25현 조율 표시 | 곡의 조성에 맞는 조율(B-1에서 정한 목록)을 추천하고, 조율 밖 음에 **"누름" 표시**를 오버레이로 그린다(라벨처럼 저장 안 함). 줄 번호 표시는 B-1 결과에 따라 선택 | 조율 검사 없이 음역만: 25현에서 실제로 칠 수 있는지 알 수 없다 |
| 9 | 출력 | MusicXML `<part-name>`·`<score-instrument>`에 악기 이름, PDF 머리글에 악기·조율. MIDI 음색은 그대로(일반 MIDI에 국악기 없음). 향피리 이조 기보는 B-1 결과가 "이조"일 때만 MusicXML `<transpose>`로 | 국악기 음색: 샘플과 라이선스 필요, 다음 단계 |
| 10 | 기존 E2E | 화면 구조가 바뀌는 테스트는 **새 흐름의 조작으로 다시 쓰되 확인하는 결과는 그대로**. `?start=` 진입은 `/record`·`/new`로 바꾸고, 옛 주소는 새 주소로 넘긴다 | 옛 구조를 숨긴 채 유지: 코드가 두 벌이 된다 |

권고안에 없는 세부는 구현 기본값으로 정하고 작업 기록에 "구현 기본값"으로 적는다.

## 5. 두 트랙의 연결

- 결정 2·3의 첫 단계에서 **목표 악기**를 고를 수 있다. 피아노가 기본값이다.
- 향피리나 25현을 고르고 허밍하면 ④ 확인 단계에서 "악기 음역 밖 N개, 장2도 내리면 모두 들어감" 같은 추천을 바로 보여 준다(트랙 B의 B-3 기능 재사용).
  사용자가 처음 말한 "녹음을 하고 조를 옮기고"가 이 지점이다.
- 녹음 뒤에도 편집기의 "다듬기 → 악기에 맞추기"로 언제든 다시 고를 수 있다. 녹음 단계에서 조옮김을 강제하지 않는다.

## 7. 검증

- 작업마다 `npm run typecheck`, `npm run lint`, `npm run test`, `npm run check:architecture`, `npm run build`, UI 변경 시 전체 `npm run test:e2e`.
- 트랙 A: 단계별 E2E(뒤로·취소 시 악보 미생성, ④ 확정 시 1개 생성, 다시 녹음), 휴대폰·데스크톱 모드 전환, axe 0건, 키보드만으로 시작 흐름 완주.
