# 악보 올리기 1·2단계 설계 — MusicXML 읽기와 `/import` (Phase 8)

작성 2026-11-16. 상태: 사용자 검토 전(검토자 확인 반영).

## 1. 왜 만드나

허밍버드는 지금 악보를 **허밍**(녹음 채보)이나 **피아노**(건반 입력)로만 새로 만든다. 사용자는 이미 가진 악보 — 피아노 악보, 가요 악보 — 를 그대로 올려서

- 다른 조로 옮기거나(예: B♭장조),
- 25현 가야금·12현 산조가야금이 연주할 수 있는 오선보로 바꾸고 싶다.

조옮김, 악기 음역 맞추기, 조율·누름 표시, 25현 큰보표, 출력은 이미 있다(Phase 7). 빠진 것은 **악보 파일을 앱 악보로 읽어 들이는 입구** 하나다.

## 2. 사용자 결정 (2026-11-16 대화)

| 결정 | 내용 |
|---|---|
| 시작 세 가지 | 홈의 처음 시작을 **허밍으로 / 피아노로 / 악보 올리기** 세 개로 한다 |
| 올릴 형식 | 최종 목표는 **PDF·사진 인식**. 그에 더해 **MusicXML·MIDI**도 받는다 |
| B♭ | **둘 다**: B♭장조로 조옮김, 그리고 B♭ 악기(클라리넷·트럼펫)용 이조 악보 |
| 피아노 악보 | 추천안 수용: **선율만 뽑는다**(오른손 맨 위 성부, 화음은 맨 위 음, 반주는 버리고 버린 것을 보여 준다) |
| 진행 순서 | MusicXML이 PDF·사진 인식 엔진의 출력 형식이기도 하므로 MusicXML 읽기를 먼저 만든다 |

전체 단계(이 문서는 1·2단계만 다룬다):

1. MusicXML 읽기 + 선율 추출 — **이 문서**
2. `/import` 화면 + 홈 시작 3개 — **이 문서**
3. MIDI 읽기
4. B♭ 악기 이조 악보(소리는 그대로 저장, 화면·인쇄·MusicXML만 장2도 높여 적기)
5. PDF·사진 인식(정확도 시험 → 인식 서버 → 결과 MusicXML을 1단계로 넘김)

## 3. 목표 / 비목표 / 반목표

**목표**
- `.musicxml`, `.xml`(MusicXML), `.mxl`(압축 MusicXML) 파일 하나를 올려 **한 줄 선율 악보**를 새로 만든다.
- 만들기 전에 무엇을 가져왔고 무엇을 버렸는지, 무엇을 맞췄는지(리듬 반올림 등) 사용자가 본다.
- 만들 때 목표 악기(피아노·25현·12현 산조)와 목표 조를 고를 수 있고, 악기 음역 기준 조옮김 추천을 바로 본다.
- 홈에 "악보 올리기" 시작을 추가한다.

**비목표(이번에 하지 않음)**
- MIDI(3단계), B♭ 악기 이조(4단계), PDF·사진 인식(5단계).
- 화음·여러 성부·여러 파트를 그대로 가져오기. 왼손 반주 보존.
- 가져오는 도중의 음 편집(만든 뒤 편집기에서 한다).
- 기존 악보에 가져온 선율을 이어 붙이기(새 악보만 만든다).
- 셋잇단음표·꾸밈음의 정확한 기보(앱 기보 엔진이 지원하지 않는다).

**반목표(이렇게 되면 기술적으로 동작해도 실패)**
- 내용을 **말없이** 버리거나 바꾸는 것. 버린 것·바꾼 것은 반드시 목록으로 보인다.
- 파일을 기기 밖으로 보내는 것. 1·2단계는 서버가 없고, 파일은 메모리에서만 읽고 저장하지 않는다(만든 악보만 저장).
- 기존 저장 형식(Score schemaVersion 3)·Command·Undo·IndexedDB 계약을 바꾸는 것.

## 4. 사용자 흐름

홈: **허밍으로 시작**(`/record`) · **피아노로 시작**(`/new`) · **악보 올리기**(`/import`). 기존 두 링크의 이름·주소는 그대로.

`/import`는 `/record`와 같은 단계형 화면이다(같은 단계 표시·이전/다음 버튼 모양).

1. **① 파일**: 파일 선택(버튼 + 끌어다 놓기). 받는 확장자 `.musicxml .xml .mxl`. 아래에 "PDF·사진은 준비 중" 한 줄과, 그동안 MuseScore에서 PDF를 MusicXML로 바꾸는 방법 안내 링크(외부 링크는 텍스트로만, 앱이 요청하지 않음).
2. **② 확인**: 읽은 결과.
   - 미리보기 악보(`StaffView`)와 재생(`PlaybackControls`).
   - 읽은 정보: 제목, 템포, 박자, 조성, 마디 수, 음 수.
   - 고른 파트(파트가 여럿이면 고르는 선택 상자, 기본은 음이 있는 첫 파트).
   - **버린 것·바꾼 것 목록**(아래 §5.4 보고서). 아무것도 없으면 "원본 선율을 그대로 가져왔습니다".
   - 읽기 실패면 원인 한 줄과 "다른 파일 고르기".
3. **③ 바꾸기**:
   - 제목(가져온 제목이 기본값, 고칠 수 있음).
   - 목표 악기: `selectableInstruments()` 목록(지금은 피아노·25현·12현 산조). 고르면 음역·범위 밖 음 수(`analyzeInstrumentFit`) 표시.
   - 목표 조: "원래 조 그대로"(기본), 조성 목록(`KEY_SIGNATURE_OPTIONS`, 원곡과 같은 장/단), 이동 방향(가까운/상행/하행). B♭장조로 옮기기는 여기서 B♭장조를 고르는 것이다.
   - 악기 음역 기준 추천: 기존 `recommendTranspositions(score, 악기 음역)` 상위 후보를 버튼으로 보여 주고, 누르면 목표 조·방향이 그 후보로 채워진다(편집기 "악기에 맞추기"와 같은 규칙).
   - 결과 미리보기 악보(악기가 25현이면 큰보표, 조율 추천·누름 표시는 만든 뒤 편집기에서).
4. **④ 악보 만들기**: 한 번 누르면 악보 하나가 저장되고 `/editor/{id}`로 간다(두 번 눌러도 하나). 저장 실패면 `/record`와 같은 안내.

어느 단계에서 나가도 악보는 생기지 않는다.

## 5. 동작 규칙

### 5.1 파일 읽기
- 크기 상한: 파일 5 MB, `.mxl` 압축 해제 합계 20 MB, zip 항목 수 200. 넘으면 거절(압축 폭탄 방지).
- `.mxl`: 브라우저 기본 `DecompressionStream("deflate-raw")`로 직접 만든 작은 zip 읽기. **새 의존성 없음.** 저장(0)·deflate(8) 방식만 지원, 암호화·zip64 거절. 본문은 `META-INF/container.xml`의 첫 `rootfile`, 없으면 `META-INF` 밖의 첫 `.musicxml`/`.xml`.
- XML 파싱은 브라우저 `DOMParser`(외부 DTD·엔티티를 가져오지 않는다). `score-partwise`만 받는다. `score-timewise`는 "지원하지 않는 MusicXML 형식" 안내로 거절.
- 문자 인코딩: UTF-8과 UTF-16(BOM)만. 다른 인코딩은 거절.

### 5.2 시간 단위
- MusicXML `divisions`(파트·마디마다 바뀔 수 있음)를 앱의 4분음표당 960 tick으로 바꾼다. `backup`/`forward`로 성부 시간을 맞춘다.
- 정수 tick으로 떨어지지 않는 길이(셋잇단 등)와 지원 음가 합으로 기보할 수 없는 길이는 **16분음표(240 tick) 격자**로 시작·끝을 반올림한다. 반올림으로 길이가 0이 되면 그 음은 버린다. 둘 다 보고서에 마디 번호와 함께 적는다.
- 꾸밈음(`grace`), 큐 음(`cue`)은 버리고 개수를 보고한다.

### 5.3 선율 추출 (사용자 결정: 선율만)
1. 파트 고르기: 기본은 음이 있는 첫 파트. 사용자가 ②에서 바꿀 수 있다.
2. 그 파트가 두 단 이상이면:
   - **모든 단을 합쳐도 같은 시점에 겹치는 음이 없으면**(한 선율을 음높이로 나눠 적은 악보: 앱이 내보낸 25현 큰보표, 큰보표에 적힌 단선율) 모든 단을 그대로 합친다. 버리는 것이 없다.
   - 겹치면(피아노 오른손·왼손 반주) **1단(`staff` 1, 보통 오른손)**만 쓴다. 나머지 단은 버리고 "아래 단 n마디 버림"으로 보고.
   - *Claude 판단(검토 반영)*: 파트 이름이나 프로그램 이름으로 25현 파일을 가려내지 않고, 겹침 여부라는 내용 기준 하나로 정한다. §8 왕복 테스트가 이 규칙으로 통과한다.
3. 1단 안의 모든 성부(voice)와 화음(`chord`)을 모아, **같은 시점에 울리는 음 중 가장 높은 음**을 고른다(skyline). 새로 시작한 더 높은 음이 앞 음을 덮으면 앞 음을 그 시점에서 자른다. 화음에서 버린 음 개수, 겹친 성부에서 잘라낸 음 개수를 보고.
4. 붙임줄(`tie` start/stop)로 이어진 같은 음높이는 한 음으로 합친다. 마디선을 넘는 음은 기존 붙여넣기 Command가 마디선에서 나누고 붙임줄로 잇는다.
5. 쉼표는 만들지 않는다(빈 구간은 기존처럼 비워 두고 화면이 쉼표로 그린다).
6. 음높이는 MusicXML의 `step`/`alter`/`octave`를 그대로 쓴다(철자 보존). 앱이 다루지 못하는 음(MIDI 0–127 밖, 지원하지 않는 임시표)은 버리고 보고.

### 5.4 박자·조·템포·제목·못갖춘마디
- **박자**: 고른 파트의 첫 박자표. 앱이 지원하지 않는 박자(앱 박자 목록 밖, 예: 5/4)도 Score가 받는 범위면 그대로 쓴다; 못 받으면 거절. 곡 중간에 박자가 바뀌면 첫 박자로 **마디선을 다시 긋고**(음의 절대 시간은 그대로) "n마디부터 마디선이 원본과 다릅니다"로 보고.
- **조**: 첫 조표(`fifths`, `mode`; mode 없으면 장조). 중간 조 변경은 첫 조표를 유지하고 보고(음 철자는 원본 그대로라 소리·음이름은 바뀌지 않는다).
  - `mode`가 major/minor가 아니면(dorian, mixolydian 등) **같은 조표(`fifths`)의 장조**로 둔다. 조표 모양과 음 철자는 그대로라 악보는 같아 보이고, "선법(○○)은 같은 조표의 장조로 표시했습니다"로 보고. 조옮김 추천은 그 장조 기준으로 동작한다. *Claude 판단(검토 반영)*.
  - `fifths`가 −7~+7 밖이거나 조표가 비표준(`key-step` 방식)이면 거절(§5.6).
- **템포**: 첫 `sound@tempo`, 없으면 첫 메트로놈 표시, 둘 다 없으면 90(`SETUP_DEFAULTS`). 앱 범위(20–400)로 자르고 잘랐으면 보고. 중간 템포 변경은 보고만.
- **제목**: `work-title` → `movement-title` → 파일 이름(확장자 제외). 120자 상한.
- **못갖춘마디**(첫 마디 `implicit="yes"` 또는 첫 마디 길이 < 한 마디): 첫 마디를 앞에 쉼표로 채운 온전한 마디로 만든다(못갖춘 부분이 1마디 끝에 오도록). 보고.
- **반복·도돌이표·D.C./D.S.**: 펼치지 않고 적힌 그대로 한 번만 가져온다. 기호가 있으면 "반복 기호는 가져오지 않았습니다"로 보고.
- **가사·셈여림·아티큘레이션·코드 기호**: 가져오지 않는다. 있으면 종류별로 한 줄 보고.

### 5.5 만들기
- 추출 결과를 `ClipboardPayload`(음표만, 0부터 시작하는 tick)로 만들고, 기존 `buildTranscribedScore`와 같은 방식(빈 악보 + `planTranscriptionCommit` → `PasteEvents`)으로 악보를 짓는다. 초기 마디 수는 기존과 같이 8, 모자라면 늘린다.
- 목표 악기를 파트에 넣는다(`createEmptyScore`의 `instrument`).
- 음자리표: 피아노·12현이면 `analyzeInstrumentFit(...).suggestedClef`, 없으면 높은음자리표(25현은 큰보표라 무관).
- 목표 조가 "원래 조 그대로"가 아니면 지은 악보에 `transposeScore`를 적용한 결과를 저장한다(새 악보라 Undo 이력에는 들어가지 않는다).
- 저장은 기존 저장소 `create` 한 번. 결과 악보는 `validateScore`·`planPartNotation`을 통과해야 하며, 실패면 저장하지 않고 원인을 ④에 보인다.

### 5.6 거절 조건(악보를 만들지 않음)
파일이 MusicXML이 아님/깨짐, `score-timewise`, 지원 범위 밖 조표(§5.4), 파트·음이 하나도 없음, 상한 초과(§5.1), 기보 엔진 상한(`MAX_NOTATION_MEASURES` 1024 등) 초과, 결과 검증 실패. 각각 한국어 한 줄 원인과 "다른 파일 고르기".

## 6. 구조 (정해진 것)

프로젝트 규칙(Domain은 브라우저 API에 의존하지 않음, 기존 공개 진입점 재사용)에 맞춘다.

- `src/adapters/file-import/zip.ts` — `.mxl` zip 읽기(`DecompressionStream`, 브라우저).
- `src/adapters/musicxml/reader.ts` — `DOMParser`로 MusicXML을 읽어 **앱 독립 중간 표현**(파트·단·성부별 음 목록, 박자·조·템포 변화, 무시한 요소 집계)으로 바꾼다.
- `src/domain/score/melody-extract.ts`(이름은 빌더 재량) — 중간 표현 → 선율 `ClipboardPayload` + 설정 + 보고서. 순수 함수, 단위 테스트 대상.
- `src/application` — `importScoreFile(file)`(읽기 → 추출), `createImportedScore(repository, …)`(§5.5). 기존 `createTranscribedScore`와 나란히.
- `src/app/import/page.tsx` + `src/features/score-import/` — 단계 화면. `/record`의 단계 표시 컴포넌트를 재사용하거나 같은 모양으로.
- 홈(`src/app/page.tsx`)에 세 번째 시작 링크.

새 런타임 의존성 없음, 저장 형식·Command 변화 없음.

## 7. 개인정보·보안
- 파일은 브라우저 메모리에서만 읽고 어디에도 보내지 않는다. 원본 파일은 저장하지 않는다(만든 악보만 IndexedDB).
- 보안 헤더(CSP)는 그대로 통과해야 한다(새 외부 요청 없음).
- 저작권: 1·2단계는 기기 안 처리라 앱이 배포하지 않는다. 약관(P6-06) 작성 때 "권리 있는 악보만 올려 주세요"를 넣는다.

## 8. 검증
- 단위: zip 읽기(저장·deflate, 상한·zip64 거절), MusicXML 읽기(divisions 변화, backup/forward, 화음, 성부, 단, 붙임줄, 꾸밈음, 못갖춘마디, 박자·조·템포 변화), 선율 추출 규칙(§5.3), 보고서 내용, 만들기(악기·음자리표·조옮김 적용, 검증 통과).
- 테스트용 파일은 **직접 만든 짧은 MusicXML**(저작권 없는 민요·연습곡 몇 마디, 두 단 피아노·화음·셋잇단·못갖춘마디·조 변경 포함)과 그 `.mxl` 압축본. 저장소 `tests/fixtures/musicxml/`.
- 왕복: 앱이 내보낸 MusicXML(25현 큰보표 포함)을 다시 올리면 같은 선율이 된다.
- E2E: 홈 세 시작, `/import` 전 단계(`setInputFiles`), 버린 것 보고, 악기·조 선택과 추천 버튼, 만들기 한 번에 악보 하나, 나가면 악보 없음, 깨진 파일 안내. 기존 E2E 전체 통과.
- 기본 검증: typecheck, lint, test, check:architecture, build, test:e2e. Safari·실기기 미검증은 명시.

## 9. 빌더에게 맡기는 것
- 파일·함수 이름, 중간 표현의 정확한 모양.
- ② 보고서의 문구와 묶는 방식(같은 종류는 한 줄로, 마디 번호는 처음 몇 개만 등).
- ③ 추천 후보를 몇 개 보일지(편집기 "악기에 맞추기"와 맞추면 된다).
- 끌어다 놓기 영역의 모양(UI는 `ui-craft` 규칙, 기존 `/record` 화면 토큰을 따른다).

## 11. Claude가 정한 것(사용자 확인용)
- 두 단 파트: 단끼리 겹치지 않으면 모두 합치고, 겹치면 위 단만(§5.3).
- 선법(dorian 등): 같은 조표의 장조로 표시하고 보고, 범위 밖 조표는 거절(§5.4).
- 리듬 반올림 격자 16분음표, 셋잇단·꾸밈음은 반올림·버림 후 보고(§5.2).
- 박자 변경: 첫 박자로 마디선을 다시 긋고 보고. 반복 기호는 펼치지 않음(§5.4).
- 파일 상한 5 MB, 압축 해제 20 MB(§5.1). 템포 없으면 90(§5.4).
- 피아노·12현의 음자리표는 악기 맞추기 제안값으로(§5.5).
