# 악보 올리기 3단계 설계 — MIDI 읽기 (Phase 8)

근거: [1·2단계 설계](2026-11-16-score-import-design.md) §2(사용자 결정: MusicXML·MIDI도 받는다, 선율만 추출) · 단계 순서 3. 이 문서는 1·2단계 설계에 **더하는 것만** 적는다. 적지 않은 규칙(선율 추출, 박자·조·템포 처리, 만들기, 화면 ②③, 저장 한 번)은 1·2단계 그대로다.

## 1. 왜

연주 앱·건반·DAW·악보 프로그램이 가장 흔하게 주고받는 파일이 MIDI다. MusicXML이 없는 사람도 가진 MIDI 파일로 선율을 가져와 조를 옮기거나 가야금 악보로 바꿀 수 있어야 한다.

## 2. 목표 / 비목표

- 목표: `.mid`·`.midi`(Standard MIDI File 형식 0·1)를 `/import`에서 MusicXML과 같은 흐름으로 받는다. 파일은 브라우저 안에서만 읽는다.
- 비목표: 형식 2, SMPTE 시간 단위, 셈여림(velocity)·페달·피치벤드·컨트롤러, 여러 선율 동시 가져오기, 반주 분리, 연주 기록의 박자·마디선 추정(BPM 추정 포함).
- 반목표: MIDI를 서버로 보내는 것. 새 런타임 의존성.

## 3. 읽기 규칙

### 3.1 파일
- 판별: 확장자 `.mid`/`.midi`이거나 첫 4바이트가 `MThd`.
- 크기 상한 5 MB(1·2단계와 같음). 트랙 수·이벤트 수는 파일 크기로 자연히 묶인다. 길이 필드가 파일 밖을 가리키면 거절.
- 형식 0·1만. 형식 2 → "지원하지 않는 MIDI 형식(형식 2)입니다." SMPTE 시간 단위 → "지원하지 않는 MIDI 시간 형식(SMPTE)입니다." 깨진 파일 → "MIDI 파일로 읽을 수 없습니다."
- running status, SysEx(F0/F7), 메타 이벤트를 읽고 건너뛴다. 트랙 끝 메타가 없어도 트랙 길이까지 읽는다(관대하게). tick은 `시간 × 960 / division`.

### 3.2 파트
- 파트 = **(트랙, 채널)** 묶음 하나. 형식 0(한 트랙에 여러 채널)도 채널마다 파트가 된다.
- 채널 10(GM 드럼)은 파트로 만들지 않는다. 있으면 "드럼 채널은 가져오지 않았습니다" 보고.
- 파트 이름: 그 트랙의 트랙 이름(메타 0x03) → 악기 이름(0x04) → "트랙 n". 한 트랙에 채널이 여럿이면 " · 채널 c"를 붙인다. 글자는 UTF-8로 읽고, 깨지면 Latin-1로 읽는다.
- 기본 파트·파트 선택·음 없는 파트 비활성은 1·2단계 그대로.

### 3.3 음
- Note On(velocity > 0)과 같은 채널·같은 음의 Note Off(또는 velocity 0 Note On)를 **먼저 켜진 것부터** 짝짓는다. 끝나지 않은 음은 트랙 끝에서 끝낸다. 길이 0인 음은 버리고 보고.
- 음 철자: 그 시점의 조표 메타(0x59)로 `spellMidiInKey`. 조표 메타가 없으면 C장조로 철자하고 "MIDI에 조표 정보가 없어 C장조로 적었습니다"를 보고한다(사용자는 ③ 목표 조에서 바꿀 수 있다).
- MIDI에는 붙임줄·꾸밈음·큐·단(staff)·성부가 없다. 모든 음은 1단·한 성부로 넣고, 겹침은 1·2단계 skyline이 처리한다(같은 시점 가장 높은 음).

### 3.4 박자·템포·제목·마디
- 박자표 메타(0x58), 템포 메타(0x51, BPM = 60,000,000 / µs), 조표 메타를 모든 트랙에서 모아 tick 순으로 쓴다(형식 1은 보통 첫 트랙). 없으면 4/4, 120 BPM(MIDI 표준 기본값).
- 제목: 첫 트랙의 트랙 이름(형식 1의 지휘 트랙) → 파일 이름.
- 마디: 박자표로 0 tick부터 마디를 나눠 번호 1, 2, 3…을 매긴다(보고의 마디 번호용). MIDI에는 못갖춘마디 표시가 없으므로 못갖춘마디 처리는 하지 않는다.
- 가사·마커 메타는 세어 "가사 n개는 가져오지 않았습니다"로 보고(1·2단계 코드 재사용).

### 3.5 연주 기록 MIDI의 리듬 (Claude 판단)
- 악보 프로그램이 만든 MIDI는 음이 기보 가능한 위치(30 tick 단위)에 정확히 있다. 사람이 연주해 녹음한 MIDI는 대부분 그렇지 않다.
- 규칙: 고른 파트의 음 시작·끝이 **모두** 정확히 기보 가능하면 그대로 둔다. **하나라도 아니면 그 파트의 모든 음 시작·끝을 16분음표(240 tick) 격자로 반올림**하고 "연주 기록으로 보여 16분음표 단위로 맞췄습니다(n개)"를 보고한다.
- 이유: 1·2단계 규칙(기보할 수 없는 시간만 반올림)을 연주 기록에 그대로 쓰면 30 tick에 우연히 맞은 음만 남아 리듬이 지저분해진다. 파일 전체를 한 기준으로 맞추는 편이 읽을 수 있는 악보를 만든다.
- 비용: 32분음표가 섞인 연주 기록은 16분음표로 뭉개진다. 템포가 흔들린 연주는 박자가 어긋난 채 들어온다(BPM 추정은 비목표).

## 4. 화면 변경

- ① 파일 입력 `accept`에 `.mid,.midi` 추가, 안내 "MusicXML(.musicxml·.xml·.mxl) 또는 MIDI(.mid) 파일, 최대 5MB".
- 홈 소개 문구의 "MusicXML 악보"를 "MusicXML·MIDI 악보"로.
- ②③과 만들기는 그대로. 새 보고 문구 3개(드럼 채널, 조표 없음, 연주 기록 맞춤).

## 5. 구조

- `src/adapters/midi/reader.ts` `readSmfImport(bytes): { ok: true; score: ImportedScore } | { ok: false; code; message }` — Domain `ImportedScore`로 바로 만든다(중간 MIDI 표현은 파일 안에서만).
- `readScoreFile`이 MIDI를 판별해 이 함수로 보낸다(`fileTitle`·5MB 규칙 공유).
- `ImportedScore`에 `quantize?: "notation" | "performance-grid"` 같은 필드를 늘리지 않고, 리듬 규칙(§3.5)은 `extractMelody` 옵션 `rhythm: "exact-or-grid" | "grid-all-if-any-off"`로 받는다. MusicXML은 기존 값, MIDI는 새 값. 보고 코드 `PERFORMANCE_QUANTIZED`, `DRUMS_IGNORED`, `KEY_ASSUMED` 추가.
- 새 의존성 없음. Domain은 브라우저 API를 쓰지 않는다.

## 6. 검증

- 단위: 앱이 내보낸 MIDI(`writeMidi`) → 읽기 → 선율 추출이 원래 음·시작·길이·템포·박자·조와 같음(왕복). 손으로 만든 바이트: running status, velocity 0 Note Off, 겹친 같은 음(먼저 켠 것부터 짝), 형식 0 여러 채널 → 파트 여러 개, 채널 10 제외·보고, 조표 없음 보고, 연주 기록(±10 tick 흔들림) → 16분음표 격자·보고, 트랙 이름·제목, 형식 2·SMPTE·깨진 길이 거절 문구.
- E2E: MIDI 파일 올리기 → ② 요약·보고 → ③ 25현 → 만들기 한 번에 악보 하나. 기존 E2E 전체 통과.
- 미검증으로 남길 것: 외부 프로그램(DAW, 악보 프로그램, 건반 녹음)이 만든 실제 MIDI → UAT-U에 1항목 추가.

## 7. Claude가 정한 것(사용자 확인용)

1. 파트 = 트랙×채널, 드럼 채널 제외.
2. 조표 없는 MIDI는 C장조 철자 + 보고.
3. 연주 기록 판정: 음 하나라도 기보 위치 밖이면 파트 전체를 16분음표로 맞춤(§3.5).
4. 템포·박자 기본값은 MIDI 표준대로 120 BPM, 4/4(MusicXML 기본 90과 다름).
5. 못갖춘마디·BPM 추정은 하지 않는다.
